# 第 1 周：NEMU 环境调研与初步移植

- 本周开始把之前在 Spike 上完成的 litmus 测试框架迁移到 NEMU 上
- 完成了 NEMU 的获取、编译和基本运行验证
- 调研了 NEMU 和 Spike 在运行方式上的差异，发现 NEMU 不能直接套用 Spike 的多核运行方案
- 参考 Spike 版框架，搭建了 NEMU 版 harness 的基本结构
- 完成了启动、编译、输出等基础适配工作
- 本周结果：程序已经可以编译成 NEMU 能加载的文件，但运行时还会卡住，下一步需要重点解决同步问题 

# 第 2 周：解决运行卡死并完成端到端验证

- 本周主要解决上周遗留的运行卡死问题
- 分析后确认，问题来自 litmus 测试本身需要多个执行流同步，而当前 NEMU 环境不能像 Spike 那样直接并行运行多个 hart
- 设计并实现了一套在 NEMU 中模拟多执行流推进的方案
- 调整了 harness 中的任务启动和等待逻辑，使测试中的多个 worker 能够依次运行并完成同步
- 最终成功跑通 `LB-mixed1`，输出结果为 `Observation LB+mixed1 Never 0 40`
- 该结果和 Spike 端一致，说明 NEMU 版 harness 已经完成基本验证
- 同时整理了使用文档和设计说明，方便后续复现和继续扩展
